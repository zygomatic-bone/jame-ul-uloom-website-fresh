# Jame-ul-Uloom Website

Static site (HTML, CSS and JavaScript, as the original site was) plus a small PHP layer for the website's own hosting. **Upload `public/` as the web root (`public_html`) and `jame-server/` next to it, not inside it** (see "Deploying on jameululoom.org"). Everything under `tools/` is the generator (Python, build time only, nothing from it runs in the browser) and its tests. There is no database or login: the forms send an email to the office and keep a private copy in a file.

## What is in `public/` (113 HTML pages, about 64 MB, of which the two large Urdu PDFs are 46 MB)
- **27 root pages.** `index.html` is the only homepage (`/home` and `/home.html` redirect to `/`). Main-portal pages: About Us, Chairmen's Messages, Governing Body, Trustees, Jamia Masjid, Services, Recognitions, Institutions, Colleges (aims, mission and vision), College Regulations, Activities, Facilities pages (Transport, Smart Classrooms, Science Laboratories, Computer Laboratory, Library, Auditorium, Sports, Calligraphy Centre, Tailoring School), Bayanath (speaker profile beside the YouTube video list), Admissions, Admissions Diary 2013-14, Contact, Careers.
- **61 institution pages** in 11 folders: `ITI/`, `PUGirlsCollege/`, `DegreeGirlsCollege/`, `BCA/`, `NCPUL/`, `EngNurSchoolDEL/`, `EngPrimarySchoolDEL/`, `EngGirlsHighSchool/`, `EngBoysHighSchool/`, `ShobaehifzDel/`, `ShobaeAlimiyathDel/`. Pages whose original text was copied unchanged from another institution are shown once, on the page they describe, and the old URL redirects there.
- **25 pages of the Residential School, Banikuppa** (`ResidentialSchoolBanikuppa/`).
- `api/submit.php`: the one entry point of the forms (a few lines; the logic is in `jame-server/forms.php`).
- `portal-assets/images/` (photographs and scans, shown whole, never cropped), `portal-assets/documents/` (3 PDFs, unchanged originals), `data/bayanath-videos.json` (the cached video list).
- Routing and headers: `_redirects` / `_headers` (Netlify, Cloudflare Pages) and `.htaccess` (Apache) carry the same 94 legacy-URL redirects, the `/home` rule and the same security headers. They are generated; none contains credentials or server paths.

## Design refinement layer (typography, navy header band, touch targets)
- `tools/portal-ui/refine.css` is the last stylesheet in `portal.css` (and, with `refine-rs.css`, in the Residential School's `assets/css/refine.css`). It only adds to the existing design system. To go back to the previous look, remove it from the lists in `generate_portal.py` / `generate_site.py` and run `python3 tools/build.py`.
- **Fonts** are self-hosted (`tools/portal-ui/fonts/`, about 125 KB, SIL Open Font License, see `NOTICE.txt`): Inter for text, a renamed subset of Lora ("Jamia Serif") for headings. `tools/make_fonts.py` documents how the files were cut; the CSP already allows `font-src 'self'`.
- **Inner-page header band:** every page's `.page-hero` is navy and gold like the homepage hero (forest green in the Residential School, whose home hero is green). Bayanath and Contact keep their own headers. The colours are the `--band-*` variables.
- **Navy dark theme on every portal page** (`refine-portal.css`); the Residential School keeps its green dark theme.
- Reading width is capped at about 40rem on essays and letters; touch controls reach 44 px on phones. The homepage's markup and light-theme layout are unchanged.

## Build and check
```bash
python3 tools/build.py          # school site, then root + institution pages, then the checker
python3 tools/check_site.py     # checker on its own
python3 -I -m unittest discover -s tools/tests -v    # unit tests (updaters, forms, page/handler agreement, security headers); the PHP ones are skipped if `php` is not installed
python3 tools/import_recovered_assets.py <original public_html>   # only when the recovered pictures must be re-imported
```
`check_site.py` fails on: a broken link, image, script or `#id`; a redirect whose target or `#id` is missing, or that chains; any link to or file named `home.html` at the root; forbidden files in `public/` (design sources, thumbnail caches, server config backups, archives, keys); inline `<script>` bodies or `style=` attributes (the CSP forbids them); images without `alt`.

## Where the content comes from
- `tools/content_main.py`, `content_more.py`, `content_inst.py`: the recovered text, written as Python so every page is regenerated. `rc_helpers.py` holds the figure, scan, table and document components.
- `tools/recovery_assets.py` lists every recovered file with its original path, alt text and caption (and `WITHHELD`, the originals that are never published); `import_recovered_assets.py` copies them byte for byte (the eight CMYK JPEGs are converted to RGB so browsers show their colours correctly).
- `tools/recognitions.json` lists the Awards & Recognition photographs (`file`, `caption`, `alt`, optional `role` and `date`); the files are in `public/portal-assets/recognitions/`.
- Historical conflicts (founding year, strengths, land area) are not resolved on the site: each figure appears only where its source states it, labelled with the source and its date.

## Not in this package, on purpose
Nothing from the server backup's private area (mail, cPanel files, credentials, `.htaccess` backups, `cgi-bin`). Original images still withheld: the donation flyer (three copies). Its bank details are published as text on About Us, on the owner's instruction (see "Support Our Mission" below); the flyer picture itself is not. A named student's certificate is permanently excluded by decision of the website owner. Two unidentified portraits and a stock-style picture are unpublished.

## Security
- **Headers on every page** (`public/_headers`, `public/.htaccess`, generated by `tools/generate_portal.py`): a Content-Security-Policy that allows only the site's own scripts, styles, fonts, images and media (plus YouTube thumbnails and the YouTube privacy-mode player, used by Bayanath only), no inline code, no plugins, no framing (`frame-ancestors 'none'`, `X-Frame-Options: DENY`); `nosniff`; a strict referrer policy; HSTS; camera, microphone, location, payment and USB switched off. The Residential School folder adds a stricter policy of its own.
- No page writes the query string or fragment into the page, builds HTML from data, or uses `eval`, `postMessage` or cookies. Bayanath draws the video list with `textContent` only, accepts an 11-character video id and YouTube image hosts only, and ignores everything else in the JSON.
- External links carry `rel="noopener"`. Photographs of pupils and staff are marked `noimageindex`.
- The weekly Bayanath update (`.github/workflows/update-bayanath.yml`, `tools/update_bayanath.py`) pins its GitHub Actions to commits, fetches only `https` YouTube and Google addresses, refuses redirects to other hosts, never sends the API key anywhere else, and keeps the old list if anything fails. The optional `YOUTUBE_API_KEY` is a repository secret and appears nowhere in the files.
- If Apache is the host, `Options -Indexes` is set and dotfiles, backups, logs and source maps are denied. The headers need `mod_headers`.

## Bayanath
- **Automatic updates on the real hosting:** `jame-server/bayanath-update.php` (PHP, started by one cron job) refreshes `data/bayanath-videos.json` every Saturday at 21:00 India time. See "Weekly Bayanath updates" below. The Python `tools/update_bayanath.py` and `.github/workflows/update-bayanath.yml` (Saturday 21:00 IST = cron `30 15 * * 6` UTC) are an optional equivalent for the staging site only; the real hosting needs neither GitHub nor Netlify.
- The self-tests run against a local fake YouTube; they simulate the feeds and do not contact YouTube.
- **Speaker Profile** (left column of a 40/60 two-column layout; the video cards are the right column, and on tablets and phones the speaker card comes first). Data: `tools/speaker/speaker-profile.json`; renderer: `tools/speaker/speaker.py`; photo: `tools/speaker/photo/` (the owner's file, never cropped); styles: `tools/portal-ui/bayanath.css` (loaded only on `Bayanath.html`; speaker classes start with `sp-`, video cards with `by-`, layout and background with `bz-`). Each designation carries a `verification` note for the maintainer; those notes are not shown on the page.
- **"Live Aurora Glow" background:** near-black navy with four slow CSS-gradient bands (blue, violet, teal, restrained gold; no green) that follow the pointer, a finger and the scroll position (`portal-ui/aurora.js`): eased values written to custom properties on one element, passive listeners, one frame loop that stops when nothing moves, and a self-simplifying fallback on slow devices. No images, canvas or WebGL; static under `prefers-reduced-motion`; it never blocks clicks.
- The MP3 sermons were removed at the owner's request (Bayanath is the YouTube videos plus the Speaker Profile).
- **New profile card, directly under the Speaker Profile.** The existing card (`speaker.py`, `speaker-profile.json`, the `sp-` rules in `bayanath.css`) is untouched and is tested against a byte-for-byte copy of the original (`tools/tests/fixtures/speaker-card-original.html`). The new card is a floating navy glass panel: renderer `tools/speaker/speaker_card.py`, content `tools/speaker/speaker-card.json`, styles `portal-ui/speakercard.css`, behaviour `portal-ui/speakercard.js`. Its parts, top to bottom: a slow cinematic slideshow of the six photographs the owner supplied (`tools/speaker/slides/`, shown whole, never cropped; 10 s per photograph with a 1.7 s crossfade, a very slow zoom and drift, previous/next, indicators, a visible pause/play button, swipe, arrow keys; paused while off screen, hovered, focused or in a hidden tab; not started under reduced motion), the name, roles and biography taken from the official YouTube channel's own description, a welcome line, the channel's content categories, **Latest from the channel** (the newest three videos from the same `data/bayanath-videos.json` as the video list, so they follow the Saturday update; thumbnails load only when the card is near the screen and nothing from YouTube is embedded before a click), then the official links: the primary button "Watch Lectures on YouTube" and an expandable "Explore All Channels" panel (Linktree, Facebook, Instagram, X, WhatsApp Community). To change a link, a sentence or the slide order, edit `speaker-card.json` and run `python3 tools/build.py`. Without JavaScript the photographs are a swipeable row and every link still works. The only change to the old card's surroundings is that the left column now stacks two cards, so the existing card keeps its natural height instead of stretching to the height of the video list.

## Jamia Masjid page
`Masjid.html` is built by `tools/masjid/masjid_page.py` from the owner's 20 photographs (`tools/masjid/photos/`, byte-for-byte copies, never cropped) and 10 silent, compressed videos (`tools/masjid/media/`). ## Motion and speed
- **Motion layer on every page** (`portal-ui/motion.css`, `portal-ui/motion.js`, also copied into the Residential School folder): scroll reveals, gold heading line, nav underline, dropdown fade-out, staggered mobile drawer, card and photograph hover with touch equivalents, a photograph viewer (previous, next, close, keyboard, swipe), a count-up only for the real figure on Institutions, accordion polish, and a cross-fade between pages. Hidden start states are added by script only for blocks below the fold and always removed again, so a failed script never leaves content invisible. Everything is transform and opacity; `prefers-reduced-motion` turns it off.
- **Light pages:** the background orbs are plain radial gradients, the grain layer has no blend mode, repeated cards keep their tint but do not blur what is behind them, the hero slideshow and the aurora pause when off screen or when the tab is hidden, and scroll, header and back-to-top share one handler.

## Contact, Feedback, Admissions and Careers
- Four pages in one navy-and-gold design (`tools/connect/connect_pages.py` writes the text; `portal-ui/connect.css`, `portal-ui/forms.js`). Contact: copyable address, tap-to-call numbers, email, directions link, a searchable department directory. Feedback: "Your Voice Matters. Your Thoughts Inspire Us.", a four-step conversational form with star rating and topic chips, and the thank-you message. Admissions: a five-step journey, what each institution publishes, a document checklist and an enquiry form. Careers: no vacancies are invented; area cards fill in an expression-of-interest form.
- Every fact is from the existing site or the owner's printed material. Where something is not published (current fees, dates, vacancies, office hours) the page says so and points to the office. The Trust's bank details are published only on About Us, from `tools/support/support-details.json` (see "Support Our Mission").
- The forms are ordinary HTML forms that work without JavaScript; `forms.js` adds the steps, validation messages and a background send. **Success is shown only when the server answers 200 `{"ok":true}`**; otherwise the visitor's text stays in the form and a mail link with the text is offered. On a host without PHP (for example Netlify) the forms therefore say honestly that nothing was sent.
- No résumé or certificate upload is offered (nothing sensitive is stored); the forms ask only for what the office needs.

## Deploying on jameululoom.org (cPanel / Apache with PHP 7.4 or later)
1. Upload the **contents of `public/`** to `public_html/` (including `.htaccess`).
2. Upload the **`jame-server/`** folder to the account's home folder, *next to* `public_html`, not inside it. (If your host forces everything under `public_html`, `jame-server/.htaccess` and `jame-server/data/.htaccess` deny web access, but next to it is much better.)
3. In `jame-server/`, copy `config.sample.php` to `config.php` and edit it: `mail_to` (where messages go, now `jamiaululoom@gmail.com`), `mail_from` (create a real mailbox such as `website@jameululoom.org` in cPanel, Email Accounts, so the messages are not treated as spam), `allowed_hosts`, and a long random `salt`. Set `data` folder permissions to 0700 and files 0600 if the host does not already.
4. If `jame-server` is not found (an unusual layout), add to `public_html/.htaccess`: `SetEnv JAME_SERVER_DIR /home/ACCOUNT/jame-server`.
5. Open `https://jameululoom.org/Feedback.html`, send a test message and check that it arrives and that `jame-server/data/logs/forms.log` says `sent`. If it says `MAIL FAILED`, the host's `mail()` is blocked: ask the host, or switch to a mailbox the host allows.
6. Messages are also kept privately in `jame-server/data/submissions/YYYY-MM.jsonl`. They contain visitors' details: keep that folder private and delete old files when no longer needed.
- Protection built in: POST only, 24 KB limit, the request must come from the site's own host, a hidden trap field, a minimum fill time, per-visitor and overall rate limits, strict field checks, no header injection, nothing echoed back, nothing cached.

## Weekly Bayanath updates (on the hosting, no GitHub or Netlify)
`jame-server/bayanath-update.php` reads the official channel (`@MuftiMaqsoodImran`, id `UClF-O3ig9ZKMvbeKB4t9mjQ`, taken from the existing configuration), adds new Bayanath videos to `public_html/data/bayanath-videos.json`, keeps existing ones, removes duplicates and keeps the newest ten. Visitors' browsers re-check that file every time the page opens, so a new video appears without any redeploy.
1. Do steps 1 to 3 above (the updater uses `config.php` too; its settings are optional).
2. In cPanel open **Cron Jobs** and add one job every 30 minutes (Minute `*/30`, everything else `*`) with the command `/usr/local/bin/php /home/ACCOUNT/jame-server/bayanath-update.php >/dev/null 2>&1` (the path of `php` is shown on the Cron Jobs page, or ask the host; an `ea-php82` style path is fine).
3. That is all. The script itself works out whether it is Saturday 21:00 in **Asia/Kolkata**, so the server's time zone does not matter. It runs once per week at the first tick at or after that time, retries on later ticks if YouTube is unreachable (up to 6 attempts), and catches up if the server was off. Every other tick exits at once without contacting YouTube.
4. Test now: `php /home/ACCOUNT/jame-server/bayanath-update.php --force --dry-run` (nothing is written), then without `--dry-run`. The log is `jame-server/data/logs/bayanath.log`.
- Safe by design: only one run at a time; the published file is replaced only by a complete, validated list (temporary file, then rename); on any failure the previous list stays, and the last 8 replaced lists are kept in `jame-server/data/bayanath-backup/` (to restore one, copy it over `data/bayanath-videos.json`). Only `https` YouTube and Google addresses are contacted.
- An optional YouTube Data API key (`youtube_api_key` in `config.php`, outside the public folder, sent in a header, never logged) reaches back 50 uploads and gives exact dates; without it the public RSS feed (the newest 15 uploads) is used, which is enough for a weekly check.
- Limits to know: if the host has no cron jobs, no PHP command line, or blocks outgoing connections, the weekly update cannot run there; the fallback is to run `python3 tools/update_bayanath.py` somewhere that can and upload `data/bayanath-videos.json` by hand, or to use the staging workflow. A browser-only script cannot do this job.
